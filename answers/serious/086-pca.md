# PCA

Principal Component Analysis finds the orthogonal directions of maximum variance in your data and
projects onto the top `k` of them. It is the optimal **linear** dimensionality reduction under
squared reconstruction error.

```
   original 2-D data              rotate to the variance axes      keep PC1
        │      ●●                        PC2                        │
        │    ●●●●●                        │  ●                      │
        │  ●●●●●                    ● ● ●●●●●● ● ●  ─── PC1         │ ●●●●●●●●●●●
        │●●●●                             │  ●                      │
        │●●                               │                         │
        └──────────────                                             └──────────────
     correlated axes             uncorrelated, ordered by         1-D, most
                                 variance                          variance kept
```

## Mechanics

1. **Centre** the data (subtract the mean). Non-negotiable — without it PC1 points at the mean.
2. Compute the covariance matrix `C = XᵀX/(n-1)`.
3. Eigendecompose: eigenvectors are the principal components, eigenvalues are the variance explained
   by each.
4. Sort by eigenvalue, keep the top `k`, project: `Z = XW_k`.

In practice use **SVD** on the centred matrix rather than forming the covariance explicitly — it is
more numerically stable and avoids squaring the condition number. `X = UΣVᵀ` gives the components
directly in `V`.

**Standardisation vs centring** is the decision people get wrong: if features are on different scales
(income in dollars, age in years), you must standardise, or PC1 simply points along whichever feature
has the largest units. If features share a scale (pixel intensities), centring alone is right.

## Choosing `k`

* **Cumulative explained variance** — keep enough components for 90–95%.
* **Scree plot** — look for the elbow.
* **Downstream validation** — the only principled method when PCA feeds a supervised model: treat `k`
  as a hyperparameter and tune it on validation performance.

## When not to use it

**1. When you need interpretability.** Components are linear combinations of all original features.
"0.3×income − 0.7×age + 0.2×tenure" is not something you can explain to a stakeholder. Use feature
selection instead if the answer must be interpretable.

**2. When the structure is non-linear.** PCA can only rotate and project. Data on a curved manifold —
a spiral, a Swiss roll — is not helped. Use kernel PCA, UMAP, t-SNE, or an autoencoder.

**3. When variance ≠ information.** This is the deep limitation. PCA assumes high-variance directions
matter. That is not always true: a low-variance direction can be perfectly class-discriminative while
a high-variance one is just sensor noise. PCA is **unsupervised** — it has never seen your labels.
When you want discriminative directions, LDA is the supervised counterpart.

**4. For sparse or count data.** PCA densifies (centring destroys sparsity, which can be a memory
catastrophe on text data) and assumes roughly continuous features. Use truncated SVD without centring
(LSA), or NMF for non-negative data.

**5. When you have categorical features.** One-hot columns have a variance structure PCA
misinterprets.

**6. Leakage risk.** Fit PCA on the **training fold only**, inside the pipeline. Fitting on the full
dataset leaks test distribution into training (question 068).

## Related uses

* **Whitening** — divide by `√eigenvalue` to give unit variance in all directions.
* **Visualisation** — the first 2–3 components, though t-SNE/UMAP are usually better for this.
* **Noise reduction** — reconstruct from the top components, discarding low-variance directions.
* **Speeding up training** — fewer features, though modern models rarely need it.

## What an interviewer digs into next

* Why SVD rather than eigendecomposition of the covariance matrix?
* When do you standardise rather than merely centre?
* Give a case where the lowest-variance component is the useful one.
* Why is fitting PCA before the train/test split a bug?
