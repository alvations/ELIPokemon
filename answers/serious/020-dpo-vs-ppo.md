# DPO vs PPO-based RLHF

**Direct Preference Optimization** ([Rafailov et al., 2023](https://arxiv.org/abs/2305.18290))
starts from an algebraic observation: the KL-constrained RL objective has a **closed-form
optimum**,

$$\pi^*(y\mid x) = \frac{1}{Z(x)}\,\pi_{\text{ref}}(y\mid x)\exp\!\left(\tfrac{1}{\beta}r(x,y)\right)$$

Rearranging gives the reward *implied* by any policy:

$$r(x,y) = \beta\log\frac{\pi(y\mid x)}{\pi_{\text{ref}}(y\mid x)} + \beta\log Z(x)$$

Substitute that into the Bradley-Terry preference likelihood and `log Z(x)` — the intractable
partition function — **cancels**, because it appears in both the chosen and rejected terms. What
remains is a plain classification loss on the policy itself:

$$\mathcal{L}_{\text{DPO}} = -\log\sigma\!\left(\beta\log\frac{\pi(y_w|x)}{\pi_{\text{ref}}(y_w|x)}
- \beta\log\frac{\pi(y_l|x)}{\pi_{\text{ref}}(y_l|x)}\right)$$

The language model **is** its own reward model. No sampling, no reward network, no value network.

```
  PPO PIPELINE                                DPO PIPELINE
  ────────────                                ────────────
  ┌────────────┐  train                       ┌────────────┐
  │ reward     │◄──── preferences             │ preferences│
  │ model      │                              └─────┬──────┘
  └─────┬──────┘                                    │
        │ scores                                    │ (chosen, rejected)
  ┌─────▼──────┐  ┌──────────┐                ┌─────▼──────┐  ┌──────────┐
  │ policy     │  │ value    │                │ policy     │  │ reference│
  │ (training) │  │ (train)  │                │ (training) │  │ (frozen) │
  └─────┬──────┘  └──────────┘                └────────────┘  └──────────┘
        │ generates rollouts                   ONE gradient step per pair
  ┌─────▼──────┐                               no generation at all
  │ reference  │ (frozen, KL)
  └────────────┘
     4 models, online sampling                    2 models, offline
```

## The tradeoffs

| | PPO | DPO |
| --- | --- | --- |
| Models in memory | 4 | 2 |
| Requires generation during training | ✅ (slow) | ❌ |
| Implementation difficulty | high | ≈ supervised fine-tuning |
| Uses on-policy data | ✅ | ❌ (offline preference set) |
| Can exceed the preference data's quality | ✅ | ⚠️ limited |
| Reward hacking | reward model exploited | over-optimises the offline set |
| Sensitivity to hyperparameters | notorious | mild (β mostly) |

The substantive difference is **on-policy vs off-policy**. PPO samples from the current policy,
scores it, and improves — so it can explore behaviours absent from the preference dataset and
keep learning as the policy moves. DPO trains on a fixed set of comparisons generated by *some
other* policy. As the policy drifts away from that distribution, the gradient signal becomes
increasingly mismatched.

This shows up as DPO's characteristic pathology: it reliably decreases the likelihood of the
rejected response, but it also often decreases the likelihood of the *chosen* response — it
mostly learns what not to do, pushing probability mass onto unexamined third options.

## The family that followed

* **IPO** — replaces the log-sigmoid with a squared loss to avoid over-fitting deterministic
  preferences.
* **KTO** — needs only binary good/bad labels, not pairs; much easier data collection.
* **ORPO** — folds preference optimisation into SFT with an odds-ratio penalty, removing the
  reference model entirely.
* **SimPO** — drops the reference model and uses length-normalised average log-probability.
* **Online / iterative DPO** — periodically regenerate preference pairs from the current policy
  and re-run DPO. This recovers much of PPO's on-policy benefit at a fraction of the complexity,
  and is what most practitioners actually run.

## The honest verdict

DPO made preference tuning accessible: it is roughly as easy as SFT, and it is the right default
for a small team. At the frontier, well-tuned online RL still wins, which is why large labs
continue to run PPO-style (and GRPO-style) pipelines. "DPO killed PPO" was a 2023 take; the 2024–25
consensus is that iterative/online methods dominate purely offline ones.

## What an interviewer digs into next

* Show why `log Z(x)` cancels.
* Why does DPO often lower the chosen response's likelihood, and does it matter?
* When would you pay for PPO's complexity?
* What does `β` control in DPO, and how does it relate to PPO's KL coefficient?
